# 提示条样式（信息型）

## 目标

玩家看第 5 月彩排那张截图后问「这种东西会不会太多了，有些影响注意力」。本轮**不动条数、不动数据契约**，只改信息型提示条长什么样、从哪儿出来、待多久。当天改了三版，最终由玩家拍板回到「顶部横幅往下弹」。

## 输入文档

- 玩家截图：第 5 月 `M05_PREP` 开场那条 `m05_prep`（「周四下午彩排 / 王哥当客户，先把那十分钟讲顺」）
- 开发册 §11.9 字号基准、§11.10 月流程壳（提示条 700×112 主 32 / 副 26、常驻规则）、§4.10 提示条字段与抢占规则
- `scripts/WorkplaceTown.gd`：`_show_reminder_toast()`、`_show_gate_banner()`、`_fire_hints()` / `_show_hint()`
- `scripts/TownUiV2.gd` 的 `_build_hud()` / `_layout_hud()`：实机 HUD 实际坐标
- `data/story/v12m/hints.json`：36 条提示，单月 1–6 条（本轮一个字节没改）

## 关键决策（最终版）

1. **回到顶部横幅，从屏幕上方滑下来**。玩家原话「还是从上弹出来吧」。600×92、居中 `(660,36)`，起始 y=−100，0.3 秒 `TRANS_BACK` 滑入 → 停 3.0 秒 → 0.24 秒滑回并淡出。
2. **视觉沿用原来的通知条语言**：深棕 `#542f1f` 0.97、金边 `#ffc453` 2px、圆角 16、阴影 0.4/14、左侧「息」圆徽 40px，标题 23px `#ffe5a8`、副句 17px `#fff0c9`。和 `_show_gate_banner`（persist / 要玩家动手那条）同一套皮，区别只在它说完就走。
3. **默认停留 3.6 → 3.0 秒**。只影响 `hold_ms = 0` 的硬编码调用；`hints.json` 里写死的 `autoDismissMs`（2500–3000）不动。
4. **已知代价**：横幅会盖住顶部心情条（第 2 月起居中 (740,18) 440×98）2–3 秒。这是原来就有的行为，玩家这轮明确要它回来，先照办。真要挪开只能落到 y=120 一带，会蹭剧情面板的「第 N 月」那行（y=190），得连字号一起改。
5. 不碰 `persist` / gate banner / `_pending_toasts` / trigger / dismissOn；队列与埋点属中改，另一个任务。

结论：这类提示在这个画风里**必须有"一张条"的形体**，光去掉底板不行；位置挪到左栏也不行。真正该削的是频率和重复（中改 + 内容任务），不是把它变没。

## 问题

- **没拍到实机图**：游戏启动要等本机 API，本机 backend 起不来（`sqlite3.OperationalError: unable to open database file`，换 `WORKPLACE_TOWN_DB_PATH` 后进程活着但不监听 8077），`test_artifacts/` 又带 Everyone 的删除/写入拒绝 ACL，截图存不进去。样式以实机为准，玩家已看过 v2/v3，v4 待看。

- 保存失败 / 读档失败这类错误反馈也走同一条横幅，和普通提示长得一样；要不要给错误单独一档（比如红边）没定。
- 字号 23 / 17 仍低于 11.9 的 30 / 24。横幅是实心块，放大到 30/24 就得 700×112，会盖住更多——和「别挡景」直接冲突，等整体挪位时一起解。
