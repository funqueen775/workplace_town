# 日期牌月份跟不上剧情

## 目标

左上角日期牌写的月份必须和剧情真正所在的月份一致。实机截图（2026-10-30）里出现了「牌面第一月 · 上旬 · 白天 / 任务卡却是第 3 月客户来访 / 心情 6 格亮着 / 手机在右下角」，玩家据此判断成「手机和心情刚进第一个月就解锁了」——实际是牌面在说谎，不是解锁错了。

## 输入文档

- 开发册 §4.14 过场分档与跳过规则、§11.23 时序（过场是闸门）。
- 剧情册：无改动（本次只动显示口径，不动台词与节点）。
- `docs/design/全年旬界与节点日期同步.md`：日期牌的运行时状态与两个同步入口。
- `AGENTS.md`：三册口径、不预告主线、改完必跑清单。

## 关键决策

1. **根因是两处，不是一个**：
   - **翻月卡被点掉，月份格没落字**。`TransitionWipe.play_month()` 的滚月/回卷/淡换都写在 tween 回调里，玩家点一下 → `request_skip()` kill tween → 回调不跑；而 `_cell_swaps` 里只有旬卡与昼夜那两格（`play_xun`/`play_daylight` 会登记），月份格从来没登记过。`_set_date()` 在同一拍就把 `_date_month` 记成新月份，后续所有节点都判定「月份没变」，牌面于是整月停在旧月份。
   - **续玩只接月份/旗标/心情，不接日期**。`_start_month_opening()` 先写死「第一月 · 上旬 · 白天」，`_try_resume_saved_month()` 接着 `_start_month_nodes(N)` 却不同步牌面，于是第 N 月的月初卡配第一月的日期；如果再叠上第一条（点掉翻月卡），错误会一直留到月底。
2. **修在机制上，不修在某一个月**：`play_month()` 开播时把三格目标字先登记进 `_cell_swaps`，正常播完与跳过都经 `_commit_cells()` 落字；续玩走 `_write_date_plate()` 静默落字（和开局第一拍同一个出口），不补播翻月卡——这一月叫什么、第一站去哪儿，月初卡已经说过。
3. **不动跳过策略**。开发册 §4.14 写「每个旬卡第一次进入该月时不可跳」，代码里 `play_month()` 传的是可跳；这条口径差异只记录、不擅自改，因为改的是交互（点一下没反应）而本次要修的是显示。
4. **不碰心情与手机的解锁时机**。心情第 2 月起亮、手机首月带巡后给，都是对的；截图里它们「提前」只是因为牌面写着第一月。
5. **续玩不进正式开局（用户 2026-10-30 晚追认）**：存档功能还没做，点「开始游戏」必须从第 1 月开始。半成品不删——`_try_resume_saved_month()` 默认返回 false，只有 `-- --v12m-resume` 才接；这样玩家不会看到"一进来就是第 N 月"，探针也仍然能验那条路。开发册 §11.8 已按这条改口径，§15.8 记了验收。
