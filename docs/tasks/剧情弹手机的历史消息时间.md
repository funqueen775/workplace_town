# 剧情弹手机的历史消息时间

## 目标

第 3 月 E10 剧情里弹出手机时，王哥那四条消息一条一个「刚刚」，看不出哪条是月初的、哪条是会上刚到的。改成：历史消息按各自到达的批次顶一个带月份的分隔，只有新到那条是「刚刚」。

- 只改时间话的来源与显示，不动投递、红点、回复流程。
- 时间话仍只到「月 + 旬 + 时段」，不推算几号、几点（开发册 §11.19）。

## 输入文档

- 剧情册 C「E10 保证不胡说」：客户会上的手机演出那一条；月初那批是前置消息。
- `docs/design/手机收件箱与消息时间.md`：时间话格式、`_phone_thread_push`、`_fill_thread`、`peek_message` 的现有口径。
- 开发册 §4 手机节点字段（`month` / `phase` / `timeBand` / `whenText`）、§11.19。
- `AGENTS.md`：手机是通知面板；阈值与文案不写死在脚本里。

## 关键决策

1. **给 `_phone_log` 补 `time`**，而不是在面板里猜：投递时写这一批的 `_phone_date_text(node)`，玩家回复沿用这条会话最后一批的 `date`（没有才回退 `_month_phone_date_text`，同一批的回复不另起分隔），剧情里新弹的那条写这一屏节点的同一套时间话。面板 `_fill_thread` 本来就按 `messages[].time` 顶分隔，只差数据。
2. **新到那条仍是「刚刚」**：它是「此刻到的」，和历史的批次时间分开；关掉手机就不再是刚刚，所以写回 `_phone_log` 时用的是节点时间话，不是字面「刚刚」。
3. **`StoryEventPanel` 把 `_event` 传给 `_peek_phone_for_story(speaker, text, node = {})`**：月 / 旬 / 时段只在城镇那套 `_phone_date_text` 里算一次，面板不复制格式规则。旧调用（探针）不传第三个参数也能跑。
4. **不动 `_phone_threads` 的数据结构**：收件箱会话本来就有逐条 `time`；这次只补剧情弹出的历史来源 `_phone_log`。

## 问题

- 这次与另一条线在 `PhoneInboxPanel.gd` / `docs/design/手机收件箱与消息时间.md` 上有交叠（对方 19:32–19:37 还在落盘 TimeDivider 命名等改动）。本次只改注释、`_phone_log` 写入和 `_peek_phone_for_story` 的可选参数，没有覆盖对方的结构改动；后续要动同一处先对一下谁在写。
- 本次改动前已经写进 `_phone_log` 的旧条目没有 `time`，会按设计留空分隔；新开局不受影响。
- 存档里不会存 `_phone_log`（运行时内存），不存在旧档迁移问题。
