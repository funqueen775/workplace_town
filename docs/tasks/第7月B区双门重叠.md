# 任务：B 区两扇门叠在同一处（第 7 月）

## 目标

同一个区只留一扇门。第 7 月 B 区同时有「组内小工具」（`m1_tool`，首月 E02 后解锁）和「把活往前赶」（`m_grind`，第 7 月 `M07_RESULT` 后解锁），两处都写 `portal.zoneId = "B"`，各建了一扇门，取同一个 `entrance`（959,194），画面上就成了一个地方两团光圈。

## 输入文档

- `十二个月开发文档_V1.md` §4.15（到访制、立门规则；第 5 条：按 E 进去之后才在右侧列这个区的活动）、§4.15.2（只有剧情带到才立门）
- `workplace_town/data/story/v12m/activities.json`（每个去处的 `portal`）
- `workplace_town/data/town/regions.json`（各区 `entrance`：B = 959,194）
- `workplace_town/AGENTS.md`（改主流程先给方案、任务与设计文档强约束）

## 关键决策

1. **一区一扇门，不是两扇门并排。** 门代表的是"这个区能进"，不是"这一件事"。`_enter_month12_place()` 按活动取 `locationId` 进**区**室内，再 `_show_month12_place_list(zone_code)` 列出该区所有能做的事——所以 B 区天然只需要一扇门。
2. **先试过偏移，被否掉。** 最早给第二扇门加了左右 84 像素避让，两门确实分开（944,240 / 1040,272），但那是把一个地方硬拆成两处，列表也还是各进各的。改成按区合并后，偏移逻辑降级为兜底（只处理不同门键撞在地图同一片的情况）。
3. **门的分组键 `_month12_place_door_key()`**：有 `zoneId` 的按 `zone:B` 算一扇；只有 `landmark` 的按 `landmark:lawn` 各算一扇；两样都没有的按活动 id 兜底。同键已有门就直接返回，新活动只进 `_month12_unlocked_places`。
4. **列表不用改**：`_show_month12_place_list` 的筛选条件是 `not _month12_place_portals.has(pid) and not _month12_unlocked_places.has(pid)`，进了 unlocked 名单就会列出来。
5. **不新增字段**：`activities.json` 不动，`portal` 仍然只写 `zoneId` 或 `landmark`。
