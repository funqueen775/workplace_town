# 第三月旬首衔接

## 目标

第 3 月三次旬界（上旬→中旬、中旬→下旬、下旬→月末）都要有内容承接，不再是旬卡一闪就直接播下一件事。

- 上旬末说清下一旬谁找你、什么时候、在哪儿。
- 中旬开头是周会散场当场，不是"周会刚散"的事后转述。
- 下旬单独一屏，把"截图没来、那一格还空着"说出来，别让 E12 凭空"你又打开"。

## 输入文档

- 剧情册：F 桥段屏末交代、F1 中旬、G E12。
- 算法册：本月零选项、零数值变化，不需要改。
- 开发册 §4 第三月节点表与拍序列、§15.4 质量清单。
- `AGENTS.md`：屏末交代三要素、剧情必须走到才开、不预告主线、便签/通知不算剧情标题。

## 关键决策

1. **补两屏而不是改一屏**。`M03_MID` 现在一屏扛了"报两周"和"演周会"两件事，塞不下便签和去处。按 `M04_NOTICE` 的现成范式拆：报时一屏、当场一屏。
2. **合同结果三句上移到 `M03_NOTICE`**。这三句讲的是"这两周的结果"，本来就不是周会当场发生的事；留在 `M03_MID` 会让首拍必须写成"周会刚散……他要当面说一句"。
3. **接受同地点连播**。`M03_BRIDGE` → `M03_NOTICE`、`M03_NOTICE` → `M03_MID` 都在 B 区工位，会被 `SAME_SCENE_KEEP` 判成连播，不铺黄线。理由是 `M04_NOTICE` / `M02_NIGHT_1` 都这么做，时间跨度由旬卡 + 首拍报时承担；强行换落点（比如搬到水巷）等于替玩家瞬移，违反"新地点先有人递"。
4. **下旬屏只回声、不加事件**。三句全部落到上旬已立的事实（群里没人回、文档停在一月、待核那格空着），不加旗标、不动数值，避免为了衔接而新造剧情。

## 二轮扩展（同日）：全年旬界

用户反馈"好几个月都是这样"。全年扫描结果：19 处跨旬，其中 11 处首拍无报时；根子有两个——

1. **机制**：日期牌在到达后（`runner_present_story`）才翻，玩家一路走的是上一旬。已改为出发前翻（`_walk_date_first` → `_begin_month_walk`，`WorkplaceTown.gd`）。
2. **第 6 月 phase 与册子冲突**：册子上旬午后去墙、中旬上午答辩，数据标成中旬/下旬。已按册子修正 8 个节点的 phase。

另补五处旬首句（`M07_HANDOVER` / `E28` / `E31` / `E41` / `M12_CHAIR`，剧情册同步）；`E41` 原首拍把中旬栈道与下旬复盘会写成同一天，已按册子改写。校验器加第 36 条（WARN）：跨旬的 `main_story` 首屏必须报时，或写 `xunOpen`。
