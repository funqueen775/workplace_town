# 提示条队列（中改：不抢、不吞、不重复）

## 目标

现在提示不是"太多"，是"抢"：两条挨着触发时，后来的直接 `queue_free` 前一条，玩家只看到最后一条；钉住的横幅又会被下一条横幅顶掉。中改按开发册 4.10 把提示条做成**一条一条轮播**，并补上 `hint_dropped` 埋点，让下一轮删哪条有数据可依。

这一轮**不改提示的条数、不改 hints.json 的文案**（那是内容任务），只改调度。

## 输入文档

- 开发册 §4.10：同一时刻只显示一条、后来的进队列、队列超过 2 条丢最旧并记 `hint_dropped`；persist 不许被反馈类挤掉
- 开发册 §11.10（含 2026-10-30 修订）：信息型提示是**没有底板的浮字**（(40,286)，标题 26 / 副句 18），门槛横幅在顶部居中 y=136
- `scripts/WorkplaceTown.gd`：`_show_reminder_toast()`、`_show_gate_banner()` / `_hide_gate_banner()` / `_notice_hint()`、`_fire_hints()`、`_on_wipe_finished()` 里的 `_pending_toasts` 补显
- `scripts/v12m/` 的月流程：`node_started` / `month_started` 的触发点
- 上一轮：[提示条降噪.md](提示条降噪.md)

## 方案

### 数据结构

```gdscript
## 待播的信息型提示。每项：
## { "title": String, "sub": String, "hold_ms": int,
##   "hint_id": String,        # 数据来的带 id，硬编码的为 ""
##   "source": String,         # "hint" | "shell"
##   "enqueued_msec": int,     # 入队时刻，判过期
##   "seq": int }              # 同帧顺序，排错时看日志用
var _toast_queue: Array[Dictionary] = []
var _toast_active := false          # 当前有一条在显示
var _toast_seq := 0
const TOAST_QUEUE_MAX := 2          # 4.10：超过 2 条丢最旧
const TOAST_STALE_MS := 6000        # 排队超过 6 秒就不播了（迟到播报比不播更糟）
const TOAST_GAP_MS := 250           # 两条之间的空隙
const TOAST_DEDUPE_MS := 8000       # 同标题同副句 8 秒内只播一次
```

### 接口（对外签名不变）

`_show_reminder_toast(title, sub, hold_ms := 0)` 保持原签名，**49 处调用一行不改**；内部改成 `_enqueue_toast()`。

新增内部函数：
- `_enqueue_toast(title, sub, hold_ms, hint_id, source)`
- `_pump_toasts()` —— 决定下一条播不播
- `_build_toast(item) -> Panel` —— 把现在 `_show_reminder_toast` 里的建面板那段原样抽出来
- `_clear_toast_queue(reason)` —— 换节点/翻月时倒掉

### 调度规则

1. **入队去重**：与"正在显示的那条"或"队列里任意一条"的 `title + sub` 相同，且距入队不到 8 秒 → 丢弃，记 `hint_dropped`（reason=`dedupe`）。`手机有消息`、`门口亮了` 那两对重复的硬编码靠这条自然合并。
2. **溢出**：入队后队列长度 > 2 → 丢队首（最旧），记 `hint_dropped`（reason=`overflow`）。
3. **不打断**：`_toast_active` 为真时只入队，绝不 `kill()` 当前 tween。当前那条播完（tween 的 `queue_free` 回调里把 `_toast_active = false`）再过 `TOAST_GAP_MS` 才 pump 下一条。
4. **过期**：pump 到队首时若 `now - enqueued_msec > TOAST_STALE_MS` → 丢弃并记 `hint_dropped`（reason=`stale`），继续看下一条。
5. **过场**：`_wipe.is_playing()` 时不 pump（不是不计数）。过场结束在 `_on_wipe_finished` 里 pump 一次。这样"压黑场"那条规则（4.10 第 0 优先级）继续成立，`_pending_toasts` 整个删掉，由队列取代。

### persist / info 的让位规则

两类提示现在**占的位置不同**（persist 顶部居中 y=136，info 左上 (36,284)），几何上不重叠，所以**不做位移重排**，只定语义：

1. persist 优先级更高，但它**不打断**正在显示的 info，也不要求 info 让位——两条同时在场是允许的，因为区域不同、不会互相盖。
2. persist 之间仍是"新的顶旧的"（`_show_gate_banner` 开头那次 `_hide_gate_banner()` 保留）：同一时刻只该有一条"必须做"。
3. info **不排队等 persist**：persist 常驻可能一整屏，等它会把提示拖成过期。
4. 带动作的 persist（整块可点的那种）也遵守第 2 条。

### 清空时机

| 时机 | 动作 | 为什么 |
|---|---|---|
| `node_started:<id>` 换节点 | `_clear_toast_queue("node")`，**在 `_fire_hints` 之前** | 上一屏的提示不该飘到下一屏 |
| `month_started` | 清空 | 翻月是新一屏 |
| 月末卡 / 月流程结束 | 清空 | 同上 |
| 过场开始 | 不清，只暂停 pump | 过场会补显，清了就白写 |
| 剧情面板打开 | 不清 | `node_started` 的提示本来就是这时出的 |
| 正在显示的那条 | 不清（只在切节点时允许它自然播完） | 半路掐断就是现在这个毛病 |

### 埋点

`ApiClient.record_event("hint_shown"/"hint_dropped", {...})`，字段：`hintId`、`title`、`month`、`source`、`reason`（`overflow|stale|dedupe`）、`queuedMs`。`source = "shell"` 的（硬编码）只报 `title`。

离线时 `record_event` 本来就会静默失败，不影响流程。

### 验收（探针 `tools/hint_queue_probe.tscn`）

1. 同一帧连发 3 条：第 1 条完整播完 → 第 2 条接上 → 第 3 条溢出被丢，日志有 `hint_dropped overflow`。
2. 第 1 条显示期间插第 2 条：第 1 条不被掐断（这一条是本次的核心）。
3. 过场中发：黑场期间不出现，过场结束补显。
4. 队列里放一条 7 秒后再 pump：被丢，`hint_dropped stale`。
5. 同标题同副句连发两次：只播一次，`hint_dropped dedupe`。
6. gate banner 在场时发 info：两条同屏、各在各的位置，info 不被 banner 挤掉。

回归：`V12CoreFlowTest` / `V12MilestonesTest` 至少不新增红；`v12m_validate.py` 不动数据，应仍是 0 错。
