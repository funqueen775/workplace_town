# 第 2 月两晚的昼夜节奏

## 目标

第 2 月后半段不能再"一直是晚上"。玩家看到的时间要按戏里的走：白天在工位 → 天黑 → 回宿舍睡觉 → 天亮回工位（白天）→ 天黑 → 再回宿舍睡觉 → 白天再回工位 → 那天夜里提交。

用户原话（2026-10-30 晚）：「第二个月后半部分一直都是晚上，应该先是白天然后去工位，然后晚上然后回去睡觉，然后白天再去工位，再到晚上再回去睡觉。」

## 输入文档

- 《剧情册》第二月 C 段「一周里的两晚（第三天、第四天）」与 D 段 E03「上旬末的夜里」。
- 《十二个月开发文档_V1》附录 A 第 2 月屏序、§4.14 过场分档、§11.23 时序、§15.10 本轮验收。

- `AGENTS.md`：屏末交代三要素、剧情必须走到才开、不预告主线、改完必跑清单。

## 关键决策

1. **一屏只能有一个时段，天亮天黑就得单独一屏**。原来的 `M02_DAY_2` 把「第四天早上」和「一抬头又到天黑」装在同一屏，屏内换时段牌面翻不出来——这正是玩家看到"早上却写着夜里"的来源。拆成 `M02_DAY_2`（白天）+ `M02_NIGHT_2`（夜里），天黑才看得见。
2. **睡觉那一屏写 `night`，睡醒后那一屏写 `morning`**。`_do_sleep()` 醒来固定 `_date_then(月, wakePhase, "morning")`，但 `_walk_date_first()` 在出发前就翻牌：下一屏要是还写 `night`，玩家从宿舍走回工位的一路都是夜里，天亮等于没发生。`M02_WEEK_7` 因此从「第七天夜里」改成「第七天早上」，天黑留给 E03 的提交夜。
3. **不新造事实，只搬句子**。`M02_NIGHT_2` 的两拍全部来自原 `M02_DAY_2` 第三拍与 `M02_WEEK_7` 首拍的时间词；「第七天十一点」这类旧说法随三张字卡一起退役。新增屏不弹新道具、不新开地点，仍在 B 区工位。
4. **每次睡觉那屏补 `departNote`**。收尾句兜底按「同区换时段」会自动补「天亮了，还在这…接着办」，而这一屏是熄灯前，方向正好反了。两处睡觉屏各写一句「先回去睡」，把兜底压住（第 2 月原本三屏也都有 `departNote`，这次只是跟着拆屏）。
5. **顺手把第 2 月的 `day` 记回戏里的日子**。评审写「周三」却记 `day 8`、E03 写「上旬末」却记 `day 14`、月末记 `day 15`，和旬对不上；改后派活 1 / 评审 3 / 书院 3 / 两晚 3·4·4 / 第七天 7 / 提交 10 / 月末 10。只动数据、不动玩法，`day` 在十二个月这条线不显示（`dateStyle: xun`），只影响事件卡的明暗与旧链路的到期判定。

## 问题

- 《剧情册》原来写着「第七天夜里回到工位 / 第七天夜里 旁白」，和"天亮回工位、当晚提交"对不上。已同步改掉 C 段三处时间词（夜里→早上、「明天提交」→「该提交了」），改前备份在根仓 `剧情册_bak_第七天早上.docx`。
- 第 2 月 E03 之后仍是「上旬 → 下旬」一跳（手册补页、月末消息、月末卡都在下旬·夜里）。这是全月"月末=下旬·夜"的既有口径，本次没动；玩家在那儿会看到一次跨旬卡，属预期。
- 本机 shell 对 `workplace_town/` 的写入被 Windows 权限挡住（`python tools/...` 能跑，但脚本写文件会 Access denied）。数据是用编辑工具改的；ACL 已按 `diagnose-windows-sandbox-acl` 补了一轮，shell 侧仍受限，删除临时文件也需要提权。
- 两个 Godot 场景测试的既有失败照旧（`V12CoreFlowTest` 的 NPC 交流入口、`V12MilestonesTest` 的第 6 月检查点），本轮复跑结果一致。
