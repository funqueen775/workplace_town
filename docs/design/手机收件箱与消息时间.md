# 手机收件箱：消息时间与分隔

## 目标

手机里的往来会横跨好几个月，同一个人（王哥）的会话里会同时出现第 2 月和第 3 月的消息。聊天里的时间分隔必须带月份，玩家一眼能看出先后；同一批消息只顶一个时间药丸，不一句一个。

实机问题（2026-10-30 截图）：王哥会话里依次是「今天 10:00 / 今天 10:00 / 周三上午」，第三条是第 3 月开场的消息，看起来却像回到了过去——分隔没有月份，时间话还是客户端编的「今天 10:00」。

## 数据结构

会话（`_phone_threads[contactId]`）：

```json
{
  "messages": [
    {"speaker": "npc", "text": "这周辛苦。", "time": "第 2 月 · 下旬 · 夜里"},
    {"speaker": "我", "text": "知道了，我提前到。", "time": "第 3 月 · 周三上午"}
  ],
  "unread": true,
  "date": "第 3 月 · 周三上午",
  "date_short": "第 3 月",
  "time_key": 300,
  "reply_options": []
}
```

| 字段 | 含义 | 写入方 |
|---|---|---|
| `messages[].time` | 这一条在聊天里顶的时间分隔（带月份） | `_phone_thread_push`；回复沿用会话最后一批的 `date` |
| `date` | 会话最后一批的时间话，回复和列表兜底用 | `_phone_thread_push` |
| `date_short` | 会话列表右上那格，只放得下月份 | `_phone_thread_push` |
| `time_key` | 最后一批的先后（月 ×100 + 旬 ×10 + 时段），只用来排列表、决定打开手机先落到谁 | `_phone_thread_push` |

`WorkplaceTown._month_phone_date_text` 另存最近投递那一批的时间话：面板打开时当 `thread_date`，玩家回复那一句也用它兜底。

交给 `PhoneInboxPanel` 的会话对象在 `_phone_conversation()` 里多带 `date_short` 与 `sort`（即 `time_key`，没聊过是 -1）。

## 时间话格式

节点只提供 `month` / `phase` / `timeBand` / `whenText`（开发册 §4 字段），客户端不推算日期与星期（开发册 §11.19：十二个月不走到天与小时）。

| 数据 | 聊天分隔 | 列表 |
|---|---|---|
| 写了 `whenText`（如「周三上午」） | `第 3 月 · 周三上午` | `第 3 月` |
| 没写 | `第 2 月 · 下旬 · 夜里` | `第 2 月` |

- 旬：`early → 上旬`、`mid → 中旬`、`late → 下旬`（复用 `_xun_text`）。
- 时段：`morning → 上午`、`afternoon → 午后`、`night → 夜里`（和剧情面板日期牌同一套词）。
- 客户端只补「第 N 月」和旬位，不改写数据给的日期话，也不把「周三」换算成几号。

## 接口

### `WorkplaceTown._phone_date_text(node) -> String`

节点 → 聊天分隔文字。`whenText` 非空时返回 `第 N 月 · whenText`；否则拼 `第 N 月 · 旬 · 时段`（缺哪格就不拼哪格）。月份缺省取 `_month12_month`。

### `WorkplaceTown._phone_date_short(node) -> String`

节点 → 列表那格的短时间，只返回 `第 N 月`。

### `WorkplaceTown._phone_band_word(band) -> String`

`timeBand → 上午 / 午后 / 夜里`，未知返回空串。

### `WorkplaceTown._phone_thread_push(contact_id, contact_name, contact_role, messages, reply_options, date_text, date_short = "", batch_key = "", time_key = 0)`

往会话追加一批消息。逐条写入 `time = date_text`；会话的 `date` / `date_short` / `time_key` 跟着这批走；`batch_key` 非空时同一批只进一次。

### `WorkplaceTown._phone_time_key(node) -> int`

`month ×100 + 旬 ×10 + 时段`。只用于排序和「打开手机先落到谁」，不参与显示。

### `WorkplaceTown._ensure_month_phone_panel()`

面板的 `thread_date` 取 `_month_phone_date_text`（最近投递那一批的时间话），不再写死「今天 10:20」。逐条消息没带时间时（刚投递的那批、玩家回复）用它兜底。

### `PhoneInboxPanel._fill_thread()`

画每个气泡前先看这条的 `time`；和上一条相同就跳过，不再重复加药丸。没有 `time` 的沿用 `thread_date`。

### `PhoneInboxPanel.peek_message(contact_id, sender_name, sender_role, history, text)`

剧情里弹手机：`thread_date = ""`，只有新到那条带 `time = "刚刚"`。历史消息各带自己那批的 `time`（`_phone_log` 投递时就写进去），按批次顶分隔，不会被「刚刚」一起盖住；没有 `time` 的历史条目就不顶分隔。

### `WorkplaceTown._peek_phone_for_story(speaker, text, node = {})`

剧情弹手机入口。`node` 是台上这一屏的剧情节点（`StoryEventPanel` 把自己的 `_event` 传进来），用 `_phone_date_text(node)` 算这条的时间话，写进 `_phone_log`；玩家关掉手机后回到剧情。`_phone_log` 的条目是 `{speaker, text, time}`，`time` 来自投递批次、玩家回复或这一拍。

### `WorkplaceTown.runner_deliver_phone(node)` / `_on_month_phone_reply_sent(...)`

投递与回复都往 `_phone_log` 追加带 `time` 的条目：投递用这一批的 `date_text`，回复沿用这条会话最后一批的 `date`（同一批发出的回复不另起分隔）。

### `PhoneInboxPanel._open_conversation(conversation_id)` / `_scroll_to_latest()`

会话能攒到十几个月，点进去必须先停在最新那条。`_open_conversation` 在 `_fill_thread()` + `_apply_view()` 之后 `await _scroll_to_latest()`（等一帧让容器算完高度，再滚到底）；`open_phone()` 的单条聊天分支和 `_on_reply_pressed()` 也走同一个出口。不滚到底的话，第 11 月点开小赵，看到的是第 3 月的信，回复键却是第 11 月的（2026-10-30 实拍）。

### `PhoneInboxPanel.open_phone(show_list := false)`

打开手机直接落在「最近还没看的那位」的会话上，并且停在最新一条；都看过了就落在最近有消息的那位。一条消息都没有才显示会话列表。`show_list = true` 用于样张/探针强制停在列表。

`_newest_conversation_id()` 先按 `sort` 倒序找 `unread` 的，找不到再退回第一条有消息的会话——HUD 红点亮的正是这个人，点开手机就该看见他。

### `PhoneInboxPanel._ranked_conversations()`

会话按 `sort` 倒序：最近有消息的排最上面，没聊过的（`sort = -1`）垫底；同分按原顺序。`_fill_list()` 与 `_newest_conversation_id()` 都用它，保证「打开落在谁」和「列表第一行」是同一套顺序。

### `PhoneInboxPanel._add_conversation_row(conv, row_w)`

列表行优先用 `conv.date_short`，没有才回退 `conv.date`。那格宽 88px、字号 `_small_font - 2`，放不下「第 3 月 · 上旬 · 上午」。

### `PhoneInboxPanel._add_date(text, font_size)`

时间药丸节点名 `TimeDivider_<序号>`：同名会被 Godot 改成 `@PanelContainer@xx`，截图脚本与探针就认不出来了。

## 依赖与边界

- 手机是通知面板，不做自由私聊；这里只动时间显示、打开落在哪条和列表顺序，不动消息投递与回复流程。
- 时间话不新增数据字段；`whenText` 仍是数据侧给的剧情日期话（开发册 §11.19）。
- 旧 48 个月与 `TownUiV2` 的旧聊天页不在本口径内。

## 验收

- 跨月会话的分隔带月份，顺序读得出来：`第 2 月 · 下旬 · 夜里` → `第 3 月 · 周三上午`。
- 同一批两条消息只顶一个分隔；回复跟在同一批下面，不再新起药丸。
- 列表那格是 `第 N 月`，不溢出、不写「今天」。
- 首月手机交接的分隔是 `第 1 月 · 上旬 · 上午`，不是「今天 14:20」。
- 剧情弹手机：历史气泡按各自批次顶分隔（`第 3 月 · 上旬 · 上午`），只有新到那条顶一个 `刚刚`；历史没有 `time` 的才留空。
- 长会话点开停在最新一条：第 11 月开小赵（7 批、`scroll_max` 1446）落在底部（`scroll_vertical=866`），不是停在第 3 月。
- 点开手机直接落在最新那条上：关掉再点开，`_active_id=xiao_zhao`、`_view=chat`、`scroll=866`；不是停在会话列表。
- 会话列表按最近消息倒序：`xiao_zhao | wang_ge | chen_gong | xiao_lin | lao_zhou`（没聊过的垫底）。
- `tools/phone_time_probe.tscn` 输出 `聊天里的分隔=第 2 月 · 下旬 · 夜里 | 第 3 月 · 周三上午`、`回复后的分隔` 同值、`首月交接=第 1 月 · 上旬 · 上午`、`剧情弹手机的分隔=第 2 月 · 下旬 · 夜里 | 第 3 月 · 周三上午 | 刚刚`、`长会话 scroll=866 / max=1446`、`重开手机落在=xiao_zhao / 视图=chat / scroll=866`、`列表顺序=xiao_zhao | wang_ge | chen_gong | xiao_lin | lao_zhou`。
