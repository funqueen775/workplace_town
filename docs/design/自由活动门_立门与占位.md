# 自由活动门：立门与占位

> 本文只写实现：门什么时候立、按什么分组、站在哪儿。玩法口径以《十二个月开发文档_V1.md》§4.15 为准。

## 1. 门是什么

`scripts/TownPortal.gd`（`Node2D`）画的一团程序化光效，零贴图。两个状态：

- `sealed = false`：金色，弧在转，粒子在飘。
- `sealed = true`：整扇压成石板灰，弧和粒子停住，走近只给「这个月还不能进」。

「已解锁 ≠ 能进」：解锁只负责把门立起来，能不能进由 `_month12_place_window_open()` 决定（剧情面板开着、过场锁着的时候一律进不去）。

## 2. 一扇门 = 一个区

门不是"某件事的入口"，是"这个区能进"。按 E 进的是区室内，进去之后右侧列**这个区所有能做的事**（`_enter_month12_place` → `_show_month12_place_list(zone_code)`）。所以：

- 同一个区无论挂几处去处，镇上只有一扇门（B 区：组内小工具 + 把活往前赶 → 一扇门、列表两行）。
- 后来解锁的活动只进 `_month12_unlocked_places`，不再多长一扇。

## 3. 数据结构

`data/story/v12m/activities.json` 每个去处：

```json
{
  "id": "m1_tool",
  "name": "组内小工具",
  "portal": { "zoneId": "B" },
  "unlockAfter": "E02",
  "apCost": 1
}
```

- `portal.zoneId`：先在哪个区的入口立门（取 `data/town/regions.json` 的 `entrance`）。
- `portal.landmark`：少数没有区的去处，坐标写死在 `_month12_place_position_of()`（`heart_lake` / `waterway` / `lawn`）。
- `unlockAfter` / `unlockHook`：二者至少一个，校验器第 26 条会把关。

运行时两张表：

| 表 | 键 | 值 | 含义 |
|---|---|---|---|
| `_month12_place_portals` | `activity_id` | `TownPortal` | **有门的那个活动**；一个区最多一条 |
| `_month12_unlocked_places` | `activity_id` | `true` | 所有已解锁去处（含共用同一扇门的） |

## 4. 接口

| 函数 | 作用 |
|---|---|
| `_ensure_month12_place(activity_id)` | 解锁一个去处：先记 unlocked，再看这个区的门是否已在，没有才建 |
| `_month12_place_door_key(activity)` | 门的分组键：`zone:B` / `landmark:lawn` / `activity:<id>` |
| `_month12_place_position_of(activity)` | 纯落点：`zoneId` 取区入口，`landmark` 查固定表 |
| `_month12_place_free_position(base)` | 兜底避让：同点已被别的门占着时左右 84 一档试六档，再上下 96 |
| `_month12_place_taken(point, occupied)` | 距离小于 72 像素判为占位 |
| `_month12_place_window_open()` | 现在能不能进门（面板没开、不在过场、处在可自由走动的相位） |
| `_update_month12_nearby_place()` | 选最近的一扇门，给「按 E 进去 · 活动名」 |
| `_begin_month_nodes_after_start_card(month, nodes)` | 月初卡"继续"后：第 2 月先弹心情讲解卡（`_hud_button_tutorial_config("mood")`），点"知道了"才 `_actually_start_month_nodes()` |

## 5. 落点与兜底

1. 有 `zoneId` → 取该区 `entrance`，过 `_snap_month12_point()` 吸附到可走网格。
2. 有 `landmark` → 查固定坐标表（`heart_lake` 860,770 / `waterway` 1424,273 / `lawn` 640,900）。
3. 两者都没有 → 默认 (1008,240)。
4. 落点如果和**已存在的另一扇门**（不同门键）相距不到 72 像素，才走兜底偏移：`+84, -84, +168, -168, +252, -252`，再 `+96, +192, +288` 向下；全占满退回原点。
5. 每个候选点都重新吸附，偏移后不能落进湖里或墙里。

## 6. 判定与已知边界

- 「按 E 进哪一扇」是**最近优先**，不是先到先得（`_update_month12_nearby_place` 只在距离更近时替换）。
- 剧情那一眼的门（`_story_door`，第 2 月图书馆）不在门表里，不参与分组也不参与避让。
- 门是灰的也占位：玩家看得见"那儿有一个区，只是现在不能进"。
- 列表按 `unlocked` 过滤，不按"有没有门"过滤——共用门的第二个去处靠的就是这条。

# 自由活动卡：用新美术把"本区能做什么"铺成一列卡（2026-10-31）

> 素材到了 12 张，`assets/01_带缩略图面板/`。本文往上那几节讲"门"，这节讲"进了门看到什么"。玩法口径仍以开发册 §4.15 为准；这里只写这一层怎么落。

## 7.1 三层结构（沿用，不新增第四层）

1. **镇上一扇门 = 一个区**。见 §2，不动。
2. **进门 = 本区能做的事**。现在是纯文字行，改成**卡片列表**：一屏一列，每行一张横卡，可滚。
3. **点卡 = 到访确认页**。仍走 `PlaceVisitPanel.show_confirm()`，不新开一套确认。

卡片只负责"选哪件"，不承担结算。结算仍在活动结果页。

## 7.2 卡面：图只出零件，字一律现读数据（2026-10-31 改）

素材是整卡：`assets/01_带缩略图面板/<区>_<活动>_面板.png`，1200×340，区名、活动名、一句话、消耗数字全烙在像素里。

**不能直接把整卡贴上去**——烙的字和游戏的账对不上，逐条核过：

| 卡上烙的 | 游戏里实际 | 后果 |
|---|---|---|
| E 区两张印「财务部」、H 区两张印「生产部」 | E 是松风训练谷、H 是慢生活园（`ZONES`），A–D 才是部门名 | 玩家进门看到的区名和地图上那块牌子不是一套 |
| 「小馆咖啡聊天」 | 这条活动叫「销售部外摆」（`m3_waterway`） | 同一件事两个名字 |
| 「桌游馆」 | 叫「桌游角」（`m11_boardgame`） | 同上 |
| 每张都印「消耗 1」 | 有卡面的四条 `hCost` 全是 0；`m11_reproduce` 反倒是 2 | 卡上的数字是假的 |

（那套部门口径不是凭空来的：`assets/八大区域地图重制版/` 里 E–H 也叫 `E_财务部.png`…，但游戏实际用的是 `assets/场景内部图/松风训练谷.png` 那一组。图给的是旧口径。）

所以这一层只从图上取**不会错的两样零件**，其余照图的版式现画：

| 位置 | 内容 | 数据来源 |
|---|---|---|
| 左上胶囊 | 区名 | `_month12_zone_name(zone_code)`，读 `ZONES` |
| 左 | 缩略图 | `assets/ui/activity_cards/thumb_<区>_<活动>.png`（脚本切出来的） |
| 中 | 活动名 + 一句话 | `activity.name` / `_month12_place_row_note()` |
| 右 | 「消耗」+ 蜂蜜罐 + 数字 | `activity.hCost` |

**蜂蜜罐是心情，不是格子。** 全游戏蜂蜜罐只表示心情 H（HUD 顶上同款），所以右栏数字读 `hCost`。`hCost = 0` 时罐子压暗、写「不花」——实拍里写 0 会画成一个方框，而且"消耗 0"读着像坏数据。占几格走中间那行小字（`占 1 格 · …`），口径和右侧窄栏那条列表一致，由 `_month12_place_row_note()` 统一给。

零件由 `python tools/v12m_cut_activity_cards.py` 切，输出 `assets/ui/activity_cards/`。图重画了就重跑这个脚本，界面不用改。

## 7.3 数据结构

不新增字段：`cardArt` 指整卡，`ActivityCardList` 从文件名取 `<区>_<活动>` 这段 key 去找切好的缩略图（也支持显式 `cardKey` 覆盖）。

```json
{
  "id": "m3_waterway",
  "name": "销售部外摆",
  "locationId": "C",
  "location": "C 区销售部外摆",
  "slots": 1,
  "hCost": 0,
  "cardArt": "res://assets/01_带缩略图面板/C_COFFEE_小馆咖啡聊天_面板.png",
  "card": { "title": "…", "lines": ["…", "…", "…"] }
}
```

- `cardArt` 空 = 这条没美术，列表退化成**纯文字行**，不塌、不留白框。
- 缩略图找不到时退回整卡，图没了再退回文字行——三层兜底，缺图不会开天窗。
- `card.lines` 是**解锁卡**的正文，不是票根卡的。两张卡分工见 §7.3.1。

### 7.3.1 票根卡 ≠ 解锁卡（这是两张不同的卡，别混）

| | 票根卡（本节） | 解锁卡 |
|---|---|---|
| 什么时候出现 | 玩家走进这个区、要挑去哪儿 | 这一处**刚开**的那一刻，一次性的 |

| 点它做什么 | 发 `activity_selected(id)` → 进到访确认页 | 「知道了」关掉；「带我去」才导航 |

解锁卡本来就在跑，`tools/unlock_card_direct_probe.tscn` 是它的专项核对；`tools/activity_cards_shot.tscn` 现在顺手把两张都拍一遍（`test_artifacts/activity_cards/` 下 `列表_*.png` 是票根，`解锁卡_*.png` 是解锁卡）。

## 7.4 接口

| 函数 | 变化 |
|---|---|
| `InteriorPreview.set_activities(activities, enabled, remaining)` | 先读 `activity.cardArt`，`ACTIVITY_CARDS` 表只兜底；每行按自己的 `disabled` 压灰；没整卡的走 `_draw_activity_ticket()` |
| `InteriorPreview._draw_activity_ticket(slot, dict, can_go)` | **新增**：同版式现画票根（牌子 / 名字 / 小字 / 消耗 + 蜂蜜罐），文字全读数据 |
| `ACTIVITY_SLOT_AT / _SIZE / _STEP` | **新增常量**：整卡和现画票根共用同一套格子坐标，两种卡不会错开 |
| `ActivityCardList.open(zone_title, items, points_text)` | `"page"` 那版（`scripts/v12m/ActivityCardList.gd`，CanvasLayer 150），面板高度跟内容走 |
| `_show_month12_place_list(zone_code)` | 组行时带 `badge` / `cost`；按 `MONTH12_CARD_SURFACE` 决定摆哪儿 |
| `_month12_zone_name(zone_code)` | **新增**：区名读 `ZONES`，票根左上那块牌子用它 |
| `_month12_place_plain_note(act)` | **新增**：只给"去那儿干什么"，不带代价前缀；`_month12_place_row_note()` 在它前面按需加「占 N 格 · 」 |
| `_begin_month12_activity(activity_id)` | 不变。卡片点击 → 同一个到访确认 |

`enabled` 判定顺序：活动没解锁 → 不再出现（列表已过滤）；心情 `H = 0` 且这条不缓心情 → 灰，理由「今天只能缓一缓」；`H = 0` 且这条能缓 → 留着能按，理由改写成「能缓过来一点 · 就按这个」。

## 7.5 卡的三态

| 态 | 画法 | 实装 |
|---|---|---|
| 可点 | 票根原样，整行是一张透明按钮 | ✅ |
| 不可点 | 整张压 55% 灰 + 左下一行理由，按钮 `disabled`，点不动 | ✅（理由来自 §7.4 的 `enabled` 判定） |
| 已完成 | 同不可点，理由写「这个月已经来过」 | ❌ 还没接：同月重复去现在仍按老路走，不压灰 |

划过不缩放也不提亮：票根本来就 1100 宽，缩放会糊，提亮又和压灰那态混在一起看不清。

## 7.6 与现有活动的关系（2026-11-01 更新：F 区已补两条）

活动表现在 12 条。美术那 12 张整卡按区码分组，接上数据的情况：C 区两条（湖边散步、销售部外摆）、E 区两条（草坪运动、团队密室未接）、D 区两条未接、H 区两条（桌游角接上、夜间烧烤篝火未接）、**F 区两条 2026-11-01 补上**：`m5_stage` 舞台后台排练、`m5_umbrella` 雨天共伞，名字和一句话直接照卡面上烙的字写，`unlockAfter: M05_DEMO`（第 5 月客户 Demo 把玩家带到观澜会展码头，小林带队、老周在场），挂进第 5/7/9/11 月的自由活动池。G 区两条（文娱室合唱/KTV、夜间值守/资料整理）仍未接：一是暖邻康护院全年剧情里没出现过，按"新地点先有人递"得先给它一场戏；二是这两个名字超过校验器的 8 字卡面上限，硬写短又和卡面烙的字打架。

## 7.7 验收

1. 带票根的卡点开后进到访确认页，扣的心情与卡右栏数字一致（`hCost = 0` 显示「不花」）。

### 7.13.1 两条毛病与修法（2026-10-31）

**毛病一：有三条纯花不回报。** 人事部长桌（2 心情）、复现论文（2 行动点 + 2 心情）、把活往前赶（1 心情）——数据里 `stateDelta` 是空的，只留一个旗标。玩家花掉点数和心情，屏幕上什么都没多。这不满足"每个去处至少一个非零效果"的本意（旗标玩家看不见）。

修法：各补一个玩家能感觉到的回报。

| 活动 | 现在 | 改成 |
|---|---|---|
| 人事部长桌 | 2 心情，无 | 2 心情，**协作 +1**，并留一份「申报表底稿」进档案材料栏 |
| 复现论文 | 2 行动点 + 2 心情，无 | 同上，**技能 +1**，并留一份「复现记录」进材料栏 |
| 把活往前赶 | 1 心情，无 | **技能 +1** |

**毛病二：只有心情 +1 的几条，像凑数。** 天台、湖边、草坪、桌游、露台、合唱，给了 1 点心情就完了，后面再没人提。修法不是加数值，是**各留一句回响**——后面某屏多一句话，让玩家知道自己那天去过：

| 活动 | 补的回响 |
|---|---|
| 天台休息 | 第 5 月熬夜那屏一句："上次在天台吹的那会儿风，这会儿想起来" |
| 湖边散步 | 第 12 月记忆墙回放里，多一条"你在湖边走过很多次" |
| 草坪运动 | 第 7 月转正那天一句 |
| 桌游角 | 第 11 月那句"上次赢你的是谁" |
| 书院露台吹风 | 第 4 月一句 |
| 文娱室合唱 | 第 10 月一句 |

**另外"太简单"这件事**：到访那一屏现在只有一段结果。改成至少三拍——进门一句处境（今天这儿什么样）、做事时一句（你在做什么）、离开时一句结果（带走了什么）。**耗心情的那几条带一次小选择**（做多少 / 要不要逞强），让"花心情"这件事本身是个决定，而不是扣款通知。

### 7.13.2 活动该加哪个属性（2026-10-31 修订，覆盖 7.13.1 里"补技能 +1"的说法）

**先纠正一个前提**：心情掉得少，不是因为活动给得少，是这本账本身天花板太低——H 上限 6、月初回满、一次最多扣 2，而且十个去处里七个 `hCost: 0`。全年实测最低只到过 5。想让"累"有意义，得先改这本账，不是往活动里塞更多扣钱项。

**能加的账，五本，按可行性排：**

| 账 | 现状 | 能不能用在活动上 | 代价 |
|---|---|---|---|
| **能力五格**（档案里那五排） | 现成，`abilityTags` → `_record_ability_tags`，还自带"长了一点 / 长进了一块"那句 | **能，首选** | 阈值 2/5/9：活动 +1 会加速到顶，得加一条"活动最多把某一格喂到第 3 格" |
| **档案材料** | 现成，材料栏已经在显示"留下的材料" | 能，最便宜的"看得见" | 只加已有两样之外的新条目要新旗标 |
| **关系档** | 算法册有 `relationships`，**客户端一行都没实现** | 要新建一本账（每个 NPC 一条档位）才能用 | 成本中等，且和"手机邀约"那套要打通 |
| **四维 S/O/N/D** | 现成 | **不建议** | 直接进 M6/M7/M12 判定，不该由"下班去玩"决定 |
| **心情 H** | 现成但天花板低 | 只作少数"硬扛型"活动的代价 | 想有效果得先抬账，见上 |

**结论**：活动给**能力五格 + 材料**，这两样玩家都看得见、也现成。关系档留给以后单独做——现在客户端连这本账都没有，挂上去也是空转。

## 7.15 自由活动是人格信号的主要来源之一（不是转正分）

先纠正一处口径：自由活动**确实**是评判大五人格的地方，而且《算法册》§3.1 早就写死了——B_t 的权重公式里有一项 `s_i`（来源类型）：**必玩 1.0 / 自由活动 0.5 / 自述 0.3**。也就是说活动进的是**人格信号轨**，权重是必玩的一半。

它不进的是**转正分**：算法册 §1「三轨不得换算」明确规定"活动奖励不能抬高 0–4 评分"，而转正只看主线选项产的证据条目。两条轨各走各的，互不折算。

**现在缺的不是设计，是落地三件：**

1. **活动埋点没人读**。每次到访已经在发 `mNN_activity`（`WorkplaceTown` 里 `record_event("m%02d_activity" …)`），但报告侧没有任何代码消费它。
2. **17 条活动都没标 B_t 信号**。每条活动至少要标：往哪个维度偏（x_i，−1..+1）、证据强弱（q_i）、情境相关度（r_i）、情境类型（独处 / 结伴 / 硬扛 / 帮人）。少了这些，活动那 0.5 的权重挂不上去。
3. **报告的"行为倾向观察"没接**。算法册 §3 的门槛是"3 个独立事件 + 2 类情境"，不够就写"观察不足"；现在报告根本没算这一段。

**信号怎么标（按活动性质粗分，具体逐条再定）：**

| 活动类型 | 例子 | 偏的维度 |
|---|---|---|
| 独处型 | 湖边散步、露台吹风、夜间值守 | 外向性偏低、内省 |
| 结伴型 | 团队密室、雨天共伞、文娱室合唱、夜间烧烤、桌游角 | 外向性、宜人性偏高 |
| 硬扛型 | 人事部长桌、复现论文、把活往前赶、松风训练谷 | 尽责性偏高；对局还带情绪稳定性 |

这样"活动丰富化"就有第二层意义：玩家常去哪儿，会变成年度报告里"你是个什么样的人"——**但不改变谁转正**。

### 7.15.1 17 条活动的人格信号标定（2026-10-31）

口径照《算法册》§3.2：只标主要信号，S/M/W = strong/medium/weak；同一活动同月重复到访**最多贡献一条**；自由活动信号权重一律 0.5，单独不足以让任何特质越过观察门槛；不把"去了某地"直接等同高特质，必须能写出**行为**和**情境**。

维度缩写：E 外向 / C 尽责 / A 宜人 / O 开放。情境四类：独处 / 结伴 / 硬扛 / 帮人（报告按"3 个独立事件 + 2 类情境"卡门槛，所以情境要分散）。

| 活动 | 情境 | 信号 | 行为（报告里能直接用的事实） |

**数据形状**（`activities.json` 每条新增）：

```json
"btSignals": [
  {"trait": "C", "dir": 1, "strength": "S", "context": "硬扛",
```

## 7.17 好感度与手机邀请（2026-10-31 设计）

### 现状（三缺）

- **有显示没数据**：档案页「人际关系」那块已经画好了（四个头像、五个空爱心、认可爪印），但读数来自后端的 `stage` 字符串；客户端自己没有关系账。
- **有规则没实现**：开发册写着"只有多人活动才能用手机约人"，但 `WorkplaceTown.gd` 里**一行邀请代码都没有**，手机面板里也没有邀请界面。
- **有名单没填**：数据里只有草坪运动、桌游角两条标了 `multi`，两条都没写 `invitableNpcs`（能约谁）。

### 好感度

- 四个人各一条档：**0–5**，对应档案上那五颗心；5 档以外另有"认可爪印"（表示他真拿你的东西用过，跟能力第 5 格呼应）。
- 增减来源：一起做完一次多人活动 **+1**；被邀请但对方没空 / 被拒绝（按剧情给的答复）**0 或 −1**；主线里替人挡事、署名让功这类事，接已有旗标给 **±1**。
- **不进转正判定**，不进能力五格；它是"这个人怎么看你"，只影响后续台词与可选做法。
- 回响：某人的档到 3 / 5 时，他身上某几屏多一句话或多一个做法；档掉到 1 以下，他会明显疏远。

### 手机邀请（多人活动专用）

触发：玩家在活动卡上选了 `mode: "multi"` 的活动、**还没走到地方**时，右下角手机自己亮一下，抽屉拉开一条：

> **要不要叫上谁？**
> · 小赵（这周在赶截图，应该有空）
> · 小林（最近在跟你核口径，未必想来）
> · 自己去

- 每条只给"他在忙什么"一句，不承诺一定来；点了就是发出邀请。
- 可以只叫一个，也可以两个都叫；**"自己去"永远留着**，不逼人社交。
- 到场后：来了的人在活动那一屏里出现、说一句话，结算给他 +1；没来的给一句"他回了句在忙"，不扣。
- 手机仍然不做自由输入——邀请是唯一"发出去"的东西（开发册既有口径）。

### 要定的

1. 现在只有 2 条多人活动，撑不起这套。是否把草坪、桌游，加上新卡里的密室 / 合唱 / 烧烤 / 共伞都标成 `multi`，各自写清能约谁。
2. 好感度够不够影响"他会不会来"——是纯剧情答复（看当期旗标），还是也看关系档。
3. 关系账放客户端还是后端：后端 `V12MState.relationships` 字段已经有了，客户端要读还是要自己记一本。
