# 全年旬界与节点日期同步

## 目标

节点进入下一屏前，左上角日期牌必须先切到该节点的月份、旬和白天/夜晚。主线走位在铺黄线前切换；手册、手机、自由活动和月末卡等非主线节点在打开自身界面前切换。相同月份、旬和昼夜不重复播放过场。

## 数据结构

节点继续使用现有字段：

```json
{
  "month": 5,
  "phase": "late",
  "timeBand": "afternoon",
  "nodeType": "phone_batch",
  "gapText": "一周后"
}
```

`gapText` 可选：写这一屏距上一屏过了多久（`两周后` / `一周后`），只进跨旬卡那一拍，不进目标卡、不预告主线。不写就照旧只换旬字。

运行时日期状态仍由 `WorkplaceTown.gd` 保存：

| 字段 | 含义 |
|---|---|
| `_date_month` | 当前月份 |
| `_date_xun` | 当前旬的显示文字 |
| `_date_band` | `白天` / `夜晚` |
| `_date_time_band` | 节点原始时段，用于记录 |

落点校验使用两级回退：先查 `MONTH_NODE_POINTS` 的节点 ID，再查 `LOCATION_POINTS` 的地点名，最后查区域入口。

## 回宿舍睡觉的时段契约（`sleepHome`）

节点写 `sleepHome: true`，表示这一屏读完不是翻下一屏，而是走回宿舍、进门熄灯、天亮再回来。**同月里凡是「夜里→白天」都要走这一条**（2026-10-30 晚定，校验器第 37 条是硬错误）：日期牌翻得再对，玩家站在原地看天亮也不成立。现在用到它的是第 2 月两晚、第 3 月收工后、第 6 月写四页那一夜、第 12 月答辩前一晚。

| 要求 | 为什么 |
|---|---|
| 这一屏的 `timeBand` 必须是 `night` | 熄灯前牌面就该是夜里。`_do_sleep()` 只压暗室内光色，不负责翻格 |
| 下一屏的 `timeBand` 必须是 `morning` | `_do_sleep()` 醒来调 `_date_then(月, wakePhase, "morning", …)`；而下一屏走位时 `_walk_date_first()` 在出发前翻牌，写 `night` 会把牌面翻回夜里，玩家从宿舍回工位的一路都挂着夜 |
| 这一屏写 `departNote` | 收尾句兜底会按「同区换时段」补「天亮了，还在这…接着办」，方向和"先回去睡"相反 |

`wakePhase` 缺省 `early`：不跨旬的那一觉只把昼夜推到「上旬 · 白天」。跨旬那一觉写 `mid`（第 3 月 `M03_BRIDGE`、第 6 月 `M06_WALL_OUT`、第 12 月 `M12_OPEN`），醒来直接是中旬，接着走下一屏。

**睡过去的那一觉可以带时间跨度（`gapText`）**：节点同时写 `sleepHome` 和 `gapText` 时，`_do_sleep()` 在黑场里用 189 层亮出那句「两周后」（`_show_sleep_gap()`），再 `_write_date_plate()` 静默把牌面写到 `wakePhase`，然后直接翻下一屏——不再补一张旬卡。第 3 月收工那一觉就是「睡过去 + 两周后」并成一拍：醒来就是中旬白天，走回工位接着演。没写 `gapText` 的（第 2 月两晚）仍走原来的 `_date_then()`。

时长口径（2026-10-30 晚按「黑场偏长 / 醒来偏快」各收一次）：

| 段 | 跨旬那一觉 | 普通那一觉 |
|---|---|---|
| 熄灯后的全黑停顿 | 1.2 秒 | 2.2 秒 |
| 「两周后」淡入 / 停 / 淡出 | 0.35 / 0.6 / 0.3 | — |
| 拉开黑场（天先亮出来） | 0.6 秒 | — |
| 醒来空一拍再开下一屏 | 0.5 秒 | 0.3 秒（原有收尾） |

全黑约 2.5 秒，最后 1.1 秒是世界已经亮起来的"醒来"那一拍，不是继续盯黑屏。

**通宵例外（`allNighter`）**：人没回去睡的那一夜（第 5 月 `M05_NIGHT` 改到凌晨）写 `allNighter: true`，校验器第 37 条放行。它不走"直接翻牌"：`_do_all_nighter()` 先压黑、在黑场里亮一句「第二天」、把牌面静默写到下一屏的旬（`_write_date_plate()`），再拉开黑场——和回宿舍那一趟同一个读法，只是不走位、不进屋。天亮仍要在下一屏首拍交代（`M05_DAWN`：「你处理完的时候，天已经蒙蒙亮」+「上旬过完了，今天就是中旬第一天」）。

**进夜也要交代（校验器第 38 条，WARN）**：天不是自己黑的。从白天进夜的那一屏，台词 / `note` / `walkNote` / `departNote` 里要出现「忙到收工 / 改到傍晚 / 天已经暗了」这类交代。第 3 月 `M03_BRIDGE` 首拍是「收工的时候，天已经黑了。回到工位。」，第 6 月 `M06_WAIT` 是「等到天黑，回到工位。」。

## 接口

### `WorkplaceTown.runner_prepare_node_date(node, then)`

非 `main_story` 节点的统一日期入口。比较节点的 `month`、`phase`、`timeBand` 与当前日期；有变化时调用 `_date_then()`，过场完成后执行 `then`，无变化时立即执行 `then`。

### `WorkplaceTown._walk_date_first(node, then)`

主线走位专用入口。行为与 `runner_prepare_node_date` 相同，但回调只负责铺黄线和设置走位状态，保证玩家移动过程中已经看到目标旬。

### `MonthNodeRunner._dispatch_prepared()`

日期入口回调。日期切换完成后才分发 `handbook`、`phone_batch`、`month_close`、`activity`；`main_story` 继续走 `runner_walk_to`，避免在没有合法落点时先改日期。

### `WorkplaceTown._do_all_nighter(month, then)`

通宵那一屏的过夜出口（第 5 月 `M05_NIGHT`）。读完这一屏先压黑 0.7 秒，用 189 层亮一句「第二天」（`_show_sleep_gap()`），再从 `MonthNodeRunner.peek_next()` 取下一屏的 `phase`，用 `_write_date_plate(month, xun, "白天", "morning")` 静默落字，然后 0.6 秒拉开黑场、空 0.4 秒才让玩家走。不走位、不进宿舍、不补旬卡：剧情里他回不去，线上还挂着告警。

### `WorkplaceTown._write_date_plate(month, xun, band, time_band)`

静默落字：直接写三格、`_record_date()`、`_apply_date_band()`，不播过场。两个调用点：

| 调用点 | 为什么静默 |
|---|---|
| 开局第一拍（`_date_month == 0`） | 玩家刚进镇，先给一个已经站好的读数 |
| `_try_resume_saved_month()` 接回第 N 月 | 开场那句「第一月 · 上旬 · 白天」是 `_start_month_opening()` 先写的；不补这一笔，左上角整月停在第一月 |
| `_do_all_nighter()` 通宵醒来 | 黑场还没拉开，牌面先落到下一屏的旬；玩家睁眼就该是白天，不该再看一张旬卡 |

续玩不再补播翻月卡：这一月叫什么、第一站去哪儿，月初卡（`MonthStartPanel`）已经交代过。

**续玩默认关（2026-10-30 晚）**：存档功能还没上线，`_try_resume_saved_month()` 直接返回 false，点「开始游戏」一律从第 1 月开始；只有命令行带 `-- --v12m-resume` 才走这条路（探针、或存档功能开做时）。上面这一笔静默落字是给它留的——打开开关时牌面必须直接是存档那一月，不能又是第一月。

### `TransitionWipe.play_month()`

翻月卡在开播时把三格目标字登记进 `_cell_swaps`（`_queue_cell_swap`），正常播完与 `request_skip()` 都经 `_commit_cells()` 落字。滚月、回卷、淡换三种动画都在 tween 回调里，tween 被 kill 时不会再跑；不预先记账，牌面就会停在上个月，而 `_date_month` 在 `_set_date()` 里已经记成新月份——从此整月对不上。

### `TransitionWipe.play_xun(old_text, new_text, xun_cell, sub_text, action_points, mirrored, band_cell, band_text, gap_text)`

跨旬卡。`gap_text` 非空时先播一拍「过了多久」：慢压暗 0.45s → 时间跨度淡入 0.35s → 停 0.5s → 淡出 0.25s → 新旬字淡进；这一拍**不甩色条、不砸字**（跨度越大动作越轻）。`gap_text` 为空走原链（旧字甩出、新字砸入 + 抖动）。`_cell_swaps` 与 `_pending_band` 的落定逻辑不变，点跳过也照样落字。

| `gap_text` | 实测时长 |
|---|---|
| 空 | 1.42 秒 |
| `两周后` | 2.67 秒 |

### `WorkplaceTown._apply_date_band(band, seconds = 0.0)`

昼夜换灯。两段渐变：入夜先 45% 时长到暖橙 `(0.86,0.55,0.32,0.22)`，再 55% 落到夜蓝 `(0.07,0.14,0.35,0.42)`；天亮先 40% 到暖白 `(0.96,0.83,0.68,0.14)`，再回到全透明。时长优先级：`seconds` > `_band_fade_seconds`（`_walk_date_first()` 预留，用完即清）> `BAND_FADE_STILL`。

| 场景 | 时长 | 常量 |
|---|---|---|
| 走位途中换昼夜 | 3.2 秒 | `BAND_FADE_WALK` |
| 原地换旬连带的昼夜切换 | 1.8 秒 | `BAND_FADE_STILL` |
| 宿舍熄灯（后面紧跟黑场） | 0.3 秒 | `BAND_FADE_SLEEP` |

信号 `band_lights` 只带一个参数，所以由 `_on_band_lights(band)` 转手，不直接连 `_apply_date_band`。

### `WorkplaceTown._set_date(month, phase, time_band, action_points = -1, gap_text = "")`

换读数并播对应档位的过场。`gap_text` 只在旬变化时传给 `play_xun()`，翻月与昼夜两档不用。`_date_then()` 多一个同名参数，`_date_wait_panel` 由 5 格扩到 6 格（面板还开着时暂存，面板一关就补播）。

## 旬界这一刻的数据：`gapText` 与旬首第一拍

跨旬时 `_set_date()` 只知道"新旬"，旬卡在玩家眼里就是"啪一下翻到下一段"。要说清"过了多久"，靠节点上的 `gapText`：

```json
{
  "id": "M04_NOTICE",
  "phase": "mid",
  "timeBand": "morning",
  "gapText": "两周后",
  "beats": [{"type": "narration", "text": "中旬，周一早上。桌上多了一张打印纸。"}]
}
```

| 字段 | 谁读 | 作用 |
|---|---|---|
| `gapText` | `_walk_date_first()` / `runner_present_story()` → `_date_then(…, gap_text)` → `TransitionWipe.play_xun(…, gap_text)` | 旬卡先单独亮一拍"两周后"，再让新旬字进来；留空就只有新旬字 |
| 第一拍 | 剧情面板 | 报时 + 地点 + 这一旬欠着的事（剧情册「旬首交代」） |

三条硬约束：

1. **同区同时段不会自动补收尾句**。`_maybe_append_departure()` 遇到"同一区、时段没变"直接跳过（那条兜底本来是给一问一答留的），所以跨旬但同地同时段的边界（第 4 月 E05 → `M04_NOTICE`）只能靠 `gapText` + 首拍自己交代，否则屏末一句都没有。
2. **`gapText` 只挂在跨旬那一屏**，同旬的屏写了不生效——`_set_date()` 只在旬变时读它。
3. **旬首第一拍不复述上一屏的结果**。上一屏结果演过的事不再抄一遍；第一拍报时，后面几拍只写这一旬才有的状态。第 4 月中旬原三句都以"两周。"开头，隔着一张旬卡和 E05 的结果说了同一件事，已改。

### 第 4 月的两处落点（2026-10-30）

| 边界 | 前一屏 | 后一屏 | 交代 |
|---|---|---|---|
| 上旬 → 中旬 | `E05`（B 区工位 · 上午） | `M04_NOTICE`（B 区工位 · 上午） | `gapText: 两周后`；首拍「中旬，周一早上。桌上多了一张打印纸。」 |
| 中旬 → 下旬 | `M04_PHONE`（夜里，手机） | `M04_LATE`（B 区工位 · 夜里） | `gapText: 几天后`；首拍「下旬。夜里，工位上还亮着几盏灯。」 |

`M04_LATE` 是这一月唯一的新屏：王哥当面把上旬那句"零散的还是没测过"再问一次，按 E05 / E07 分版回答；屏末 `departNote` 把玩家交到月末卡（"月末最后一夜。工位上的灯还亮着，这个月到这儿了。"）。

## 验收

- 19 个跨旬主线节点首拍均有旬名或时间词；
- 非主线跨旬节点在界面打开前完成旬卡/昼夜切换；
- 同旬同昼不重复播日期过场；
- 翻月卡播到一半点一下跳过，月份格立刻是目标月，不停在上个月；
- 续玩接回第 N 月，开机那一刻日期牌就是第 N 月，不靠第一屏节点的旬卡补救；
- 写 `sleepHome` 的屏是夜里、它后面一屏是白天，睡醒那一段走位不会被翻回夜里（第 2 月两晚：白天 / 夜晚 / 白天 / 夜晚 / 白天 / 夜晚）；
- `MONTH_NODE_POINTS` 和 `LOCATION_POINTS` 都能被审计器识别；
- 写了 `gapText` 的跨旬屏，卡上先亮那句时间跨度再换旬字；没写的照旧只换字，不报错；
- 第 4 月两次旬卡各带一句跨度（上旬→中旬「两周后」、中旬→下旬「几天后」），下旬有屏，月末卡不再紧跟复盘会；
- 走位途中换昼夜时，世界光照在整段路上渐变到夜里，不是一迈步就整屏变蓝；原地换旬与熄灯两档不被拉长；
- `python tools/v12m_validate.py`、`python tools/audit_v12m.py`、API 自测及两条 Godot 场景测试均记录实际结果。
