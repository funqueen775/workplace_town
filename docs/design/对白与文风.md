# 对白与文风（12m_v1）

这份文档只回答一件事：**玩家读到的那句话该怎么写**。剧情里发生什么、谁说了哪句真话、选项给多少分，一律以《剧情册》和《十二个月报告算法册_V1》为准；这里不新增事实，只改说法。

## 1. 问题记录（2026-10-30）

把游戏交给外部读者试读，反馈集中在三处：

1. **没有主语**——旁白大量写成「纸上是这个模块的两条路」「表留着。以后谁再问，先看表」这类名词句，读者不知道是谁在做什么。
2. **语序像说明书**——把「自研做一份，开源改一份。依赖和退路，各写一栏」这种表格语言直接塞进人物嘴里。
3. **五六个字断一下**——一句一个逗号，逗号之间只有四到八字，读起来是电报，不是人说话。

三条叠在一起，读者给的结论是「剧情设计太人机」。

追查发现两个结构性原因：

- 运行数据（`data/story/v12m/events.json`）里有 180 / 508 句在《剧情册》里找不到出处，是历次流程补丁顺手写的，句式最像机器。
- 《剧情册》里本来写好的分支台词（同一场戏按上月旗标换一句）在数据里被合并成一句通用台词，所有人都说同一句话，也是「人机味」的来源。

## 2. 六条硬规则

1. **有主语。** 叙述句写清谁做了什么；只有祈使句和现场对答可以省主语。
2. **句子有长短。** 单句 12–40 字，一个 beat 最多三句；出现连续三个八字以内的短句，就算节奏坏了。
3. **不许用名词句顶替动作。** 「依赖和退路，各写一栏」改成「你把这些东西分成两栏写」。
4. **台词按人分声线。** 见 §3；同一个人在不同月份不能换口音。
5. **每场留一句没用的话。** 抱怨、闲聊、动作细节都行，最多两句，不能抢主线。没有这句，场景就像在念需求文档。
6. **选项和结果写动作与后果，不写评价。** 「当场说明」可以，但结果里不要出现「这说明你重视署名」这类评语。

## 4. 禁用句式（会直接读成机器写的）

- 判断句收尾：「纸上是两条路。」「表留着。」
- 段末拔高：「今天到这儿，有收获了。」
- 四字排比三连：「谁做的，名字就写谁的」可以留一句，连着三句就是口号。
- 无主语的抽象名词开头：「依赖和退路，各写一栏。」
- 旁白替玩家解释潜台词：「你听出来了吧。」
- 同一个月里两场结构一模一样的戏（例如两次「门口那个人」用同一组选项、同一段结果）。

## 5. 数据结构：玩家可见文本字段

| 字段 | 出现在哪 | 建议字数 | 口吻 |
|---|---|---|---|
| `beats[].text`（`say`） | 对白气泡 | 20–80 | 口语，可省主语 |
| `beats[].text`（`narration`） | 旁白气泡 | 20–90 | 书面但不书面腔，必须有主语 |
| `beats[].emphasis` | 高亮词 | 4–12 | 必须是 `text` 的子串 |
| `choices[].text` | 选项行 | 6–20 | 一个动作，不加理由 |
| `choices[].outcome` | 选后结果屏 | 30–80 | 只写发生了什么 |
| `prompt` | 选项上的提示句 | 6–20 | 一句现场的话 |
| `todayCard.lines` | 「今天」卡 | ≤ 26/行 | 三行以内，只写安排 |
| `departNote` | 屏末交代副行 | ≤ 40 | 谁安排、去哪、做什么 |
| `memoryNote[].text` | 记忆墙便签 | ≤ 16 | 第一人称心里话 |
| `messages[].text` | 手机消息 | ≤ 60 | 像真的短消息，可断句 |

`beats` 里带 `when` / `notFlag` 的分支拍必须成对出现：一条给「读过手册」的玩家，一条给没读过的；不要只写一条通用句。

## 6. 接口与工具

- `tools/voice_lint.py`：只读体检。统计每个节点的平均句长、八字以内短句占比、禁用句式命中，输出可读报告；`--strict` 时命中即非零退出。它不判断好坏，只把「像机器」的量化特征摆出来。
- `tools/v12m_validate.py`：继续管事实（地点、旗标、屏末交代、禁词），文风规则不进校验器——写得好不好没法机检，只能靠 lint 预警加人工读。
- 改写顺序：`events.json` 正文 → 本册 §3 声线表（如有新人）→《剧情册》同段回写。回写没做完之前，`events.json` 是临时真相，必须在任务文档里记一条待同步。
