# 阅读负担与交互（12m_v1）

这份文档管两件事：**玩家必须读多少字**，以及**这些字凭什么非读不可**。句式怎么写归《对白与文风》；剧情事实归三册。这里只定“删什么、留什么、删了以后靠什么接住”。

## 0. 一句话口径

减字只减三类：**重复交代、提前预告、替玩家总结**。
人物台词、现场细节、每场那句闲话，一个字不动——那是体验感本体。

## 1. 账本（2026-10-30 实测，全部来自 `data/story/v12m/`）

| 来源 | 体量 | 必读？ |
|---|---|---|
| 剧情正文 | 520 拍 / 14,540 字 | 是 |
| 选项结果 | 118 条 / 3,979 字（实际只读到 1/3） | 是 |
| 屏末交代 `departNote` | 16 条 / 365 字，另有自动补句 | 是 |
| 今天卡 + 活动卡 | 25 张 / 1,050 字 | 是 |
| 手机消息 | 31 条 / 887 字 | 是 |
| 提示条 | 36 条 / 716 字 | 半 |
| 手册 | 约 1,600 字 | 可选 |
| **合计** | **≈1.85 万字 / 60 分钟纯读 / 638 次点击** | |

结论：总字数对一个 3–5 小时的叙事游戏不算离谱，**问题在密度和重复**——同一条安排一个月被讲 2–3 遍（第 2 月“去树影书院查旧单”散在 5 个屏里说了 9 次），且玩家全程只有“点”。

## 2. 可删清单（R）

| 编号 | 类型 | 判据 | 例 |
|---|---|---|---|
| R1 | 同义复述 | 同一“去哪/做什么”在同月多屏重复，且已被目标卡、走位副行或前一屏承接 | 王哥说完“周三去评审室”，屏末旁白再说一遍 |
| R2 | 预叙计划 | 旁白把“先 A、之后 B、最后 C”讲完，其中 B/C 还没发生 | “先定验证路子，评审完去书院，回来把退路写进方案” |
| R3 | 替玩家总结 | 旁白下结论、说潜台词、给评价 | “这说明你重视署名”“你听出来了吧” |
| R4 | 选项结果里的行程复述 | 三条结果各自再写一遍散会去哪 | 结果句末尾“散会后你去树影书院二楼翻旧单……” |

## 3. 必留清单（K）

| 编号 | 类型 | 说明 |
|---|---|---|
| K1 | 人物声线台词 | 每场至少 3 句能听出是谁在说的 |
| K2 | 现场细节 | 灯、纸角折痕、假绿植、包子——不承担信息，承担可信度 |
| K3 | 闲话 | 每场 1–2 句，不抢主线 |
| K4 | 屏末落点 | 每屏最后仍要说清“谁安排、去哪”。可以交给自动补句或一句 `departNote`，但必须有且只有一句 |
| K5 | 每月 `goalLine` | 一个月一句，校验器会数 |

## 4. 连贯性保障：删掉的字由谁接

删一句之前，先确认它被下面三件里至少一件接住，否则不删：

1. **自动落点句**（`WorkplaceTown.gd::_maybe_append_departure`）：跨区补“按 X 的安排，去 Y 吧”，同区换时段补“天亮了，还在这…接着办”，带选项的屏接在每条结果句后面。
2. **今天卡 `todayCard.lines`**：三行内写清“谁让你做什么”。
3. **走位副行 `walkNote`**：玩家在路上时的一行“为什么去”。

这三件都接不住的，说明信息只在那句话里——那句话就是 K，不能删。

### 逐屏自查（改完每屏都要过）

- 我在哪？——首拍有地点或画面，或上一屏落点已交代。
- 我为什么在这？——派活的人/理由在本屏或上一屏出现过。
- 下一步谁安排？——本屏有且只有一句落点。

## 5. 数据结构

### 5.1 本期（只改文案，不改 schema）

可改字段：

| 字段 | 约束 |
|---|---|
| `beats[].text` | 保留 `when` / `notFlag` 分支拍；分支拍成对保留 |
| `beats[].emphasis` | 必须是改后 `text` 的子串 |
| `choices[].text` / `outcome` | 结果 ≤60 字，只写发生了什么 |
| `departNote` | ≤40 字，一句 |
| `todayCard.lines` | ≤26 字/行，三行内 |

禁改：`id`、`month`、`order`、`locationId`、`timeBand`、`phase`、`day/hour`、`flags`、`setsFlags`、`stateDelta`、`riskDelta`、`competency`、`when`、`goalLine` 的数量（一个月恰好一条，可换承载句，不能增删）。

### 5.2 二期（交互 `probe`，本期未实现）

```json
{
  "type": "probe",
  "object": "靠窗那摞旧事故单",
  "label": "翻一页",
  "text": "……玩家点开后读到的那一句",
  "emphasis": ["加监控"],
  "setsFlag": "m02_library_read_rollback"
}
```

- 渲染：物件名 + 按钮，点开播 `text`，再点继续。
- 门槛：一屏 2–3 个 `probe`，全点过才出选项（节点字段 `probeGate: true`）。
- 约束：`probe` 只换呈现，不改事实；`setsFlag` 若被后续 `when` 消费，必须先登记进算法册旗标表。
- 客户端落点：`StoryEventPanel.gd` 加 probe 分支，`WorkplaceTown.gd` 加门禁判断；校验器加“`probeGate` 屏必须 ≥2 个 probe”。

## 6. 工具

`tools/read_load.py`（只读）：按节点输出字数、拍数；按月汇总；标出四类嫌疑——拍数 >6、结果句 >60 字、同月 4-gram 重复句对（复述嫌疑）、整屏无 `say`（可能缺人物）。它只报可疑，不判对错。

## 7. 验收

第 2 月样板（12 屏 → 改动屏：`M02_OPEN`、`E04`、`M02_LIBRARY`、`M02_NIGHT_1`、`M02_WEEK_7`）：

- 字数从 1,760 降到 ≤1,300（-26% 以上），拍数 54 → ≤46；
- 每屏 ≤6 拍（`M02_OPEN` 13→≤8，`E04` 14→≤8）；
- 每月主线任务交代 ≤2 次（派活一次 + 落点一次），不再逐屏复述；
- `voice_lint.py` 八字以内短句占比变化 ≤2pp；`v12m_validate.py` 0 错误、WARN 不新增；
- 逐屏过 §4 三问；K1–K5 一条不少。
